# ADR-NETCUP-PUBLIC-EDGE-PREP-001 — prepared Netcup edge for confenge.com.br

- **Status:** Accepted for preparation; public cutover is not authorized by this ADR
- **Date:** 2026-08-26
- **Decision state:** EXECUTE_NOW for `PREPARE_NOW`; DNS cutover remains a separate controlled decision
- **Executive front:** INBOUND ENGINE
- **Time to evidence:** this pull request (configtest, idempotency, rollback and non-regression gates)
- **Leverage:** distribution, trust and automation
- **Affected public ADR:** web-cfg `ADR-STRAT-002` remains authoritative and unchanged

## Context

`confenge.com.br` is the only canonical public visitor surface. Its current
runtime authority remains Netlify. The existing Netcup host already has a
host-owned NGINX edge for `api.confenge.com.br`, `ops.confenge.com.br` and
`auth.ops.confenge.com.br`; Caddy is private on loopback and MCP has no public
hostname.

The site needs a reversible, fully prepared destination before a future DNS
cutover can be considered. Preparing that destination must not silently change
the current runtime authority, DNS, certificates or any co-resident vhost.

## Decision

Governance owns an inert host pack at
`infrastructure/netcup-public-edge/` with these boundaries:

- host NGINX remains the only public owner of ports 80 and 443;
- the web static root is `/opt/confenge-web/current/_site` and `current` is an
  atomic release symlink;
- the only application runtime upstream is `127.0.0.1:18100`;
- structural vhost, TLS paths, proxy hardening, install, readiness and rollback
  are owned here;
- editorial redirects, 301/302/410 decisions, CSP, HSTS, cache policy,
  X-Robots and application content types are generated by the versioned
  `web-cfg` release and included from `/etc/confenge/web/current/`;
- the final vhost and the HTTP-01 bootstrap are installed disabled and no
  command reloads NGINX unless the operator supplies `--reload`;
- Certbot/Let's Encrypt remains the ACME owner. DNS-01 is preferred when a
  least-privilege provider credential already exists; HTTP-01 is the bounded
  fallback;
- the infrastructure collector declares the target as
  `PREPARED/NOT_LIVE`, so intentional pre-cutover absence is not an incident.

The expected IPv4 is not invented here. Operators resolve it from the existing
canonical production allowlist and cross-check the Control Center production
runbook. No AAAA record is declared or implied.

## Explicit non-decisions

This ADR does **not**:

- change public DNS or the Netlify runtime authority;
- issue a certificate;
- enable or reload an NGINX vhost;
- change HSTS `max-age`, `includeSubDomains` or `preload`;
- modify or replace `api`, `ops` or `auth.ops`;
- give Caddy host ports 80/443 or publish MCP;
- create a public application runtime, systemd unit, database, network or
  second data/identity plane.

A future cutover must update the web-cfg runtime authority record and present
live evidence in a separate change. It may not reinterpret this preparation as
authorization.

## Repetition test

One hundred releases reuse the same atomic release/symlink, generated-snippet,
configtest, readiness and rollback path. They improve release evidence and
reduce cutover risk; they do not require one hundred bespoke vhosts or manual
rule copies.

## Rollback

Before every installation or activation, preserve an NGINX backup and the
previous release/vhost symlink targets. Rollback restores only the
`confenge.com.br` symlinks, runs `nginx -t`, and reloads only when explicitly
requested. DNS rollback remains a separate human operation. Co-resident vhosts
are never restored from a blanket archive during ordinary rollback.
